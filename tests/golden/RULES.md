# Order page golden master: rule map

Generated by `tests/golden/rules.test.ts` from `tests/golden/rules.ts` and the scenario list. Do not edit by hand:
`GOLDEN_RECORD=1 npm test` rewrites it, and `npm test` fails when it is out of date.

- `npm test` runs every scenario on the current code and compares it with the recordings (any difference fails).
- `GOLDEN_RECORD=1 npm test` re-records. Only re-record from code whose behaviour is accepted as the new truth.
- Synthetic fixtures: `tests/fixtures/synthetic/` (built by `node tests/tools/build-synthetic-fixtures.mjs`), recordings in `tests/golden/synthetic/`.
- Real-data fixtures and recordings: `tests/golden/local/` (local only, never committed), extracted from the local test database with
  `node tests/tools/extract-local-fixtures.mjs` (refuses any server other than `mongodb://127.0.0.1:27099`).
- Recording format: per step, `events` (toasts that reached the screen, `window.confirm` texts and answers, requests with
  their bodies, router calls); step 1 holds the full page `state` (every row and `data-field`: value, disabled, title, min,
  options), later steps hold only the leaves that changed (`changes`). `expandStates()` in `tests/harness/snapshot.ts`
  rebuilds the full state of every step.

## Real-data scripts (local only)

Run on every fixture in `tests/golden/local/fixtures/` for Admin and Planner; recordings in `tests/golden/local/recordings/`.

- `load`: Open the page (rows, locks, defaults, upstream columns, General card).
- `save-as-is`: Open the page and save without editing (what a plain save sends, or which check refuses it).
- `edit-and-save`: Row 1 End 2026-12-31 and plan type Tentative (both copied down where the rules allow), row 2 remarks 'golden-check', then save.
